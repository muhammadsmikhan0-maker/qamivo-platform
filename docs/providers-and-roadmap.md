## AI and agent plan

The coding agent changes source files; Netlify hosts the site; a runtime AI provider would perform application inference; payment/video/Google integrations are separate business services. Their permissions and costs are independent. Codex is the connected coding agent. The selectable dashboard options, configured model/reasoning and current credit allowance could not be verified. No parallel agents were run.

Qamivo AI is **Deferred**. No model is selected or priced, and no SDK or inference endpoint was added. Before the later AI milestone, read the then-current Netlify AI Gateway model catalogue and official provider pricing. Choose the least-cost model that meets a measured job-brief/help task. Keep credentials server-side; use authenticated per-member quotas, persistent usage metadata and configurable spend controls; minimise prompts; avoid customer files; make provider failure explicit. Ground help in approved public content. Keep consequential financial, permission, identity and moderation decisions under human control. Do not claim third-party account access without an authorised integration.

## Costs and controls

The site snapshot exposes plan identifiers but not authoritative allowance balances or full entitlements. Netlify hosting, database provisioning/compute/storage, function requests, Identity/email, future Blobs bandwidth and runtime AI may incur usage charges under the account plan. Exact monthly cost is **unknown**, not estimated as free. The database is the managed capability requested for this project and provisions through the deployment lifecycle; no separate paid plan or spend setting was activated. No auto-recharge, credits purchase, third-party subscription or advertising budget was configured.

Current controls include bounded public lists (50), workspace/proposal lists (100), field/body limits, API rate-limit configuration, per-member mutation counters, no polling, no AI calls and no uploaded media. Pagination, wider read-side abuse verification, monitoring and budget alerts remain necessary before scale. The owner should review current dashboard quotas, rate-limit plan support, billing alerts and Identity limits before inviting a wider audience.

1. Inspect pipeline results, fix build/types/dependency findings, verify the migration in a deploy preview and exercise two-member workflows. Acceptance: actual persisted records, error states, refresh, ownership, duplicate protection and concurrent closure evidence.
2. Complete operator/legal/brand checks and email confirmation/recovery delivery; add staffed support/reporting, moderation, data export/deletion and retention controls. Acceptance: real recipient tests, abuse handling and documented owner/legal approval.

4. Build contracts, milestones, message participants, deliverable versions and eligible reviews. Acceptance: transition and object-access tests before connecting financial services.
5. Complete merchant discovery and sandbox payment/ledger/payout review. Acceptance: signed idempotent event tests and owner-approved funds flow; no live activation by default.

7. Introduce bounded AI and first-party promotion only after cost/privacy approval. Assess video, LMS and commerce as separate demand-led milestones.

Reuse this ledger and research outcomes; use one focused agent run at a time; avoid redundant builds and broad unrelated tooling. Never interpret a coding-agent credit limit as a runtime inference or advertising spending cap.
